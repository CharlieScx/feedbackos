## 1. 建立安全的验证工作区

- [ ] 1.1 创建 `validation/week-1/` 的目录说明、文件命名和 ID 规则，并通过文件清单确认访谈、样本、报告和汇总模板都有唯一归属
- [ ] 1.2 增加私有数据边界与 `.gitignore` 规则，使用一个含模拟姓名/邮箱/令牌的本地文件验证其不会被 Git 跟踪
- [ ] 1.3 编写样本授权、保留期限、删除方式和二次脱敏检查清单，并用一个缺少授权的合成案例验证状态会保持阻塞

## 2. 准备用户访谈与需求证据模板

- [ ] 2.1 编写目标对象筛选表和邀请文案，验证筛选项覆盖角色、5～50 人团队规模和反馈决策职责
- [ ] 2.2 编写 30～45 分钟访谈提纲，验证问题覆盖最近真实案例、当前流程、频率、替代方案、决策影响、失败点和反面证据
- [ ] 2.3 创建脱敏访谈记录与访谈登记模板，验证事实、原话/确认转述、研究者判断和不确定性具有独立字段
- [ ] 2.4 在访谈提纲中加入明确的再次提供数据请求，并用“明确承诺”和“只有兴趣”两个合成回答验证计数规则不同

## 3. 建立人工反馈分析契约

- [ ] 3.1 编写统一反馈字段 V1，定义必填、可选、未知值和来源批次关系，并用三种不同列结构的合成样本验证都能完成映射
- [ ] 3.2 编写问题分类 V1 的定义、纳入/排除边界和“其他/不确定”路径，并验证一条多问题反馈可以保留单一反馈 ID 和多个问题标注
- [ ] 3.3 创建样本批次登记与质量问题模板，验证未授权、未脱敏或缺少正文/稳定 ID 的记录不会进入报告统计
- [ ] 3.4 创建透明优先级工作表，验证 `frequency × severity × growth × confidence × segment_weight` 可复算，且缺少增长窗口时显示“未测量”并使用中性值 1
- [ ] 3.5 创建 Top 3 报告模板，验证每个结论必须填写支持证据 ID、反面证据、少数意见、不确定性，以及人工调序前后结果与理由

## 4. 实现确定性校验工具

- [ ] 4.1 使用 Python 标准库实现脱敏登记校验器，验证必填字段、唯一 ID、授权状态、独立批次和报告证据引用错误均返回非零退出码
- [ ] 4.2 增加不含真实客户信息的通过与失败合成夹具，运行单元测试验证访谈数、样本数、报告数和重复意愿门槛均有边界覆盖
- [ ] 4.3 生成结构化校验结果和人类可读周摘要草稿，并验证相同输入重复运行得到一致结果且不读取私有原始文件

## 5. 实现落地页与内测登记

- [ ] 5.1 创建独立静态落地页结构和中文文案，浏览页面确认首屏、适用对象、证据闭环、设计合作状态、能力边界与行动入口完整且无未验证宣传
- [ ] 5.2 在主题层映射权威 `design-tokens.json` 的浅色/深色 token，检索业务样式验证不存在裸色值或无 token 来源的尺寸，并在两种系统主题下检查可读性
- [ ] 5.3 实现最小登记表单与显式同意，验证联系方式、角色、团队规模、反馈来源、分析频率和合作意向可提交，未勾选同意时被阻止
- [ ] 5.4 实现可配置且无密钥的表单端点及提交状态，验证未配置、提交中、成功、校验失败、网络失败和重试路径，且页面不提供原始反馈文件上传
- [ ] 5.5 完成移动端、键盘、焦点、标签与错误关联检查，验证窄屏无横向滚动、所有交互可按顺序到达，并记录检查结果
- [ ] 5.6 编写本地预览、端点配置和部署说明，按文档从干净环境启动页面并验证源码与日志不包含登记令牌或用户提交内容

## 6. 执行第一周真实验证

- [ ] 6.1 招募并完成 8～10 次合格访谈，在每次访谈后更新脱敏登记，运行校验器确认只有符合目标范围且字段完整的记录计数
- [ ] 6.2 从至少 3 个不同提供方接收授权且脱敏的真实样本，在受控位置保存原始文件，并运行隐私清单确认仓库中只有批次元数据和允许使用的脱敏证据
- [ ] 6.3 使用统一字段与分类完成 3 份独立 Top 3 报告，运行证据追溯检查确认所有统计可复算且每个结论都能定位到对应脱敏反馈 ID
- [ ] 6.4 向样本提供方回访报告价值并提出下一周或下一个版本再次提供数据的明确请求，验证“已确认”记录包含时间条件、数据类型和证据说明

## 7. 周验收与继续决策

- [ ] 7.1 运行完整校验并生成第一周摘要，核对有效访谈 8～10、合规样本至少 3、独立报告至少 3、明确重复意愿至少 3 四项门槛
- [ ] 7.2 在摘要中整理支持证据、反面证据、样本限制、落地页登记漏斗和字段/分类修订建议，并由人工复核确认没有把一般兴趣计为重复承诺
- [ ] 7.3 根据已验证证据记录“继续第二周”“补充验证”或“重新评估定位”的唯一决策，并验证未达门槛时不会启动第二周产品骨架实施
